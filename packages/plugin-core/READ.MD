## 插件核心

包含三个核心模块：
用于定义 `plugin.json` 所包含的字段。

- 插件权限定义 permission.ts
- 插件的节点定义 node.ts
- 插件的配置文件定义 manifest.ts

### 插件权限定义 permission.ts

对应 `plugin.json` 中 `permissions` 字段

1. 定义了插件在运行时可以执行的操作，例如访问网络、读取文件等。
2. 预定义权限信息，包含权限类型，名称，描述，风险等级。用于前端的UI展示。
3. 定义了插件的权限验证逻辑，包含两种，在加载插件和执行插件时分别验证。
   3.1. 加载插件时，如果插件声明的权限 > 用户声明的权限 ，则插件加载失败。
   3.2. 执行插件时，用户没有授权，则抛出错误

注意事项：
如果在插件配置文件`plugin.json`中 permissions 字段为空，则插件在安装时通过，在运行时调用定义的服务都会被拒绝，只适合定义本地服务。

### 插件的节点定义 node.ts

对应 `plugin.json` 中 `nodes` 字段

1.  定义了插件节点的类型，例如工具节点、数据节点等。用于前端的UI展示。
2.  定义了节点的输入和输出，用于工作流中节点之间的数据传递。
3.  节点配置属性，对应于 `plugin.json` 中 `nodes` 字段的 `configSchema` 字段。用于定义工作流点击节点时弹出的配置表单。
4.  节点的综合定义，对应于 `plugin.json` 中 `nodes` 字段。包含上面的所有定义。
5.  定义了节点的执行结果，用于工作流中节点之间的数据传递。
6.  定义了节点的执行器接口，用于在工作流中调用节点的执行逻辑。
7.  定义了节点的执行上下文 - 节点 ID - 节点类型 - 工作流 ID - 执行 ID - 节点配置 - 节点输入值 - 日志记录器 - 服务代理
    7.1. 服务代理 `PluginServices`，定义插件运行时需要调用的服务，每个服务都需要对应的权限。（调用前需要先进行插件权限验证）
    核心作用：
    安全隔离 + 权限控制：插件运行在沙箱环境中，不能直接访问系统资源。必须通过 services 代理来使用受保护的功能，每次调用都会经过权限校验。

    设计意义
    - 安全：插件无法绕过权限直接访问敏感资源
    - 可控：管理员可以细粒度控制每个插件的权限
    - 可追踪：所有调用都会记录插件 ID 和操作类型
    - 统一入口：所有系统服务都通过统一代理，便于审计和管控

### 插件的配置文件定义 manifest.ts

整个插件的配置文件，定义`plugin.json` 中的所有字段。包含权限定义和节点定义。

1. 定义了插件的元信息：插件市场的展示和管理
   使用场景：
    - 插件市场的列表展示、搜索、筛选
    - 插件详情页的概要信息
    - 管理后台的插件管理
2. 插件版本信息：管理插件的每个版本
   使用场景：
    - 版本管理（多版本并存）
    - 版本审核流程
    - 插件升级时的版本对比
    - 运行时加载特定版本的代码
3. 插件安装信息：跟踪用户/工作区已安装的插件
   使用场景：
    - 用户已安装插件列表
    - 启用/禁用插件
    - 插件卸载
    - 插件更新检查（对比 installedVersion 和 latestVersion）
